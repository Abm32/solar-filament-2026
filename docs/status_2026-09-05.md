## Code and Evaluation Findings

1. **Validation annotation policy differs from the organizer reference.** The downloaded self-evaluation notebook evaluates predictions separately against every annotator-image entry. Our kernel selected the most complete annotation set only. The same 141 held-out files contain 217 annotator entries and 1593 annotations. V8 evaluates those entries separately, never unions conflicting annotator masks, and asserts file-level separation from training. This better follows the public evaluator, but does not establish that the hidden server implementation is identical.
2. **Flips remained disabled after conversion to a single class.** Left/right category concerns no longer apply to a foreground-only output. V8 tests horizontal and vertical flips at probability 0.5. This is a regularization hypothesis, not a guaranteed score gain. The refiner already uses flips and quarter rotations.
3. **Validation spent excessive work on dense integer products.** The prior IoU routine allocated full-resolution int32 stacks and multiplied every pixel for every GT/prediction pair. V8 uses COCO RLE IoU with `iscrowd=0` and transposes to preserve GT-by-prediction orientation. Binary masks and the strict `IoU > 0.5` matching rule are unchanged. Tests compare the result to independent logical intersection/union calculations, including intersections larger than 255 pixels.
4. **Refiner training crops are cleaner than detector crops.** Training uses exact GT-centered bounds; inference uses predicted masks. Jittered crop centers/scales and proposal-conditioned refinement are promising follow-up ablations. They need end-to-end PQ validation because crop Dice alone does not measure instance separation.
5. **Resolution can limit thin structures.** The 2048px images are trained at 1024px with mask ratio 2. Test 1280px or tiled inference in a later isolated experiment, with memory/runtime measurements and tile duplicate suppression. V8 keeps resolution fixed so its training ablation is flips.
6. **Repeated annotator variants change sampling weights.** Multi-annotated images appear more often and can contain conflicting labels. V6 helped, but uniform sampling by unique image and random annotator selection remains worth comparing.
7. **Single random split is insufficient evidence of generalization.** Images span years and observation sites; neighboring observations may be correlated. Add date/site grouped evaluation before claiming a robust improvement. V8 preserves the existing split so it does not introduce another training variable.
8. **Polygon handling needs evidence before changing.** Every one of the 8199 current annotations has exactly one polygon, so hypothetical multi-polygon instance splitting is not the current failure. Rasterization still uses rounded OpenCV polygons; compare it with the annotation producer's canonical rasterization before changing boundary targets.
9. **Reproducibility was incomplete.** V8 emits `run_manifest.json` with package versions, configuration, split IDs, and metric identity. Runtime installation still uses unpinned Ultralytics; use the recorded working version for future exact reruns.
10. **Inference is repeated across sweep candidates.** RLE IoU removes the dense scoring cost, but detector/refiner inference is still repeated across thresholds and annotators. A future per-image compressed prediction cache can reduce runtime; it must preserve score ordering and non-overlap at every threshold.
