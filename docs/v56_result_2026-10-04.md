# V56 — Mask R-CNN instance-segmentation pivot + leaderboard reframing

Date: 2026-10-03 → 2026-10-04. VM: rogii-gpu (4× T4). Firewall intact: FIT-only training,
canonical Random(42) split, no test/CSV/submission. rogii not deallocated.

## Why we pivoted (the reframing)
Pulled the live leaderboard + real public kernels (first time this project looked at the
*competition*, not just V17's own ceiling):
- **Leaderboard: top 0.63, dense cluster 0.55–0.63.** Our V17 public **0.39** is far down
  the board. The project's "0.4487 tune-PQ ceiling / hard-FN wall" (E027/E028) describes
  V17's YOLO pipeline, NOT the competition. +0.01 fusion tweaks cannot reach 0.55+.
- Public-kernel triage: `phuongncn/lb-0-70` and `lamhuy/0.55` are **fake embedded-payload
  CSVs** (verified — no method). `rokaiyasomapti/lb-1st` is a plain smp U-Net (semantic,
  known to cap low). `nomannic19/...mask-r-cnn-u-net-refiner` is a **real** instance
  pipeline: `maskrcnn_resnet50_fpn_v2` (COCO-pretrained), 1024px, score 0.60, mask 0.50.
- Internal signal (lamhuy analysis): high scorers win on **recall** (more valid instances
  across more images). V17 chronically under-recalls.

Triangulated decision: build a **Mask R-CNN** instance pipeline — the instance-aware
approach V55's learning demanded, aimed at the recall deficit, matching the one real
competitive kernel.

## What was built
`scripts/train_v56_maskrcnn.py` — torchvision `maskrcnn_resnet50_fpn_v2` (COCO weights,
2 classes), reuses V52's canonical split / annotation helpers (V52 untouched). Modes:
`train` (FIT-only) and `tune` (project PQ, score-threshold sweep, mask-thresh 0.5,
disjoint pixel ownership by descending score, upscaled to 2048). `detections_per_img=300`
(filaments are numerous; recall matters). `tests/test_v56_maskrcnn.py` (7 tests), ruff clean.

## Honest correction (recorded deliberately)
Mid-run I reported a "resolution scaling law" (1024→1536 = +0.027 PQ) and launched a 2048
sweep partly on that basis. The full sweep **refuted it**: the single 1536=0.3833 run was
**run-to-run variance**, not a trend — `1536_e40` at the *same resolution* scored 0.3579
(0.025 lower), and the two 2048 runs (0.367–0.377) did not exceed it. All variants cluster
**0.354–0.383**, below V17 (0.4487) and not reliably above V52 w1 (0.3766). I
over-interpreted one lucky checkpoint; flagged rather than buried.

## Conclusion (single-annotator GT)
Mask R-CNN (COCO-finetune) at every T4-feasible res/epoch/LR is a **local negative vs
V17** on single-annotator tune PQ. Instance-aware architecture *alone* does not break the
recall wall or reach the 0.55+ cluster. Recall caps ~0.55–0.58, FP 468–520 (vs V17's 306).
**No submission** (correctly — nothing cleared the bar).

## But this fed the real finding
The persistent ~0.35–0.38 wall across *every* architecture (YOLO/semantic/instance)
prompted the data-side investigation (user's steer, via BioHub). That investigation found
MAGFiLO annotations are **sparse/incomplete** (see
`docs/annotation_sparsity_finding_2026-10-04.md`): union-of-annotators has 1.35× the
instances of the single record we train/score on. Union-GT re-eval of these exact V56
weights shows TP↑/FP↓ (real filaments mislabelled as FP) but FN↑ (model can't cover the
fuller set it was never trained on). **Union-TRAINED** Mask R-CNN (`--target union`) is now
running — the actual test of whether learning the fuller label set lifts recall/PQ.
