# V54 — recalibrate V52 proposal scores to rescue the fusion recall path: NEGATIVE

Date: 2026-10-03. VM: rogii-gpu (4× T4). Firewall intact: gate trained on FIT only;
no tune labels in training; no test / CSV / submission. GPUs returned idle; rogii not
deallocated.

## Hypothesis
V53 proved V52 (clDice semantic U-Net) is genuinely orthogonal to V17 (FP correlation
19–24%, recovers 93/317 of V17's missed GT), yet the fusion gained only +0.0006 because
the recall path (adding V52's unmatched proposals, beta>0) was strictly harmful: V52's
mean-probability score cannot separate its recovered TPs from its many FPs. **If a better
per-proposal score existed, beta>0 could become net-positive and clear the +0.010 gate.**

## What was built (all FIT-only, firewall-safe)
- `scripts/dump_v54_fit_features.py` — runs V52 (base32 @0.40) on the 566 FIT files,
  extracts 10 cheap features per proposal + a TP/FP label (greedy IoU>0.5 vs FIT GT).
  Output: 5318 proposals, 3148 TP / 2170 FP. Features: log_area, mean_prob, max_prob,
  prob_x_area_norm, compactness, extent, elongation, solidity, skel_len_norm, skel_per_area.
- `scripts/fit_v54_gate.py` — pure-numpy standardized L2 logistic gate, 80/20 FIT AUC.
- `scripts/rescore_v54_tune.py`, `scripts/v54_fusion.py` — re-score tune dumps + re-run
  the V53 grid with recalibrated scores. (Built, ruff-clean, but NOT run — see below.)
- `tests/test_v54_gate.py` — 4 tests (sigmoid, AUC, logistic separability). Pass.

## Result: the gate is inert where it needs to be deterministic
Gate validation AUC (held-out FIT fold):

| score function | val AUC |
|---|---|
| full 10-feature gate | 0.8265 |
| gate WITHOUT max_prob (9 feat) | 0.8225 |
| mean_prob only (= the V53 score) | 0.8224 |

Two findings, both decisive:
1. **The full gate beats mean-prob by only +0.004 AUC.** Learned weights: mean_prob
   dominates (1.571); every geometric feature |w| ≤ 0.35 (compactness −0.35, skel_len
   +0.15, elongation +0.10, rest smaller). +0.004 AUC cannot flip beta from strongly
   negative (V53: beta=1.0 → PQ 0.38) to clearing a +0.010 PQ gate.
2. **All of that +0.004 comes from `max_prob` alone.** Dropping max_prob collapses the
   gate to 0.8225 = the mean_prob-only baseline. The mask-geometry features
   (compactness, skeleton, elongation, solidity, extent) carry **zero** independent
   TP/FP signal beyond mean-probability.

## Why the grid was not run (confound + inertness)
To use max_prob at fusion time, V52 must be re-run on tune to get a prob map. But V52
inference is **non-deterministic**: all 141 re-inferred tune dumps had different RLE
proposal sets than the original `base32_t040` dumps (e.g. 5 vs 4 proposals/file). A gate
arm built from re-inference therefore confounds "better score" with "different proposals"
— not a clean A/B against V53.

The only deterministic-from-dumps score (geometry + stored mean_prob, no max_prob) is
AUC-equivalent to the mean_prob V53 already used, so it would at best reproduce V53's
+0.0006. Either way the expected value is non-positive, so running the full grid would
spend GPU to confirm what the gate AUC already shows. Stopped here and removed the
confounded `/mnt/v52/cache/base32_gate` dumps.

## Conclusion
No cheap recalibration exists that is BOTH (a) deterministic from the stored dumps AND
(b) better-separating than mean-probability. **V52's false positives are not
geometrically distinguishable from its true positives** — they are confident,
filament-shaped structures that simply don't match GT. This is the same hard-FN /
ambiguous-annotation wall (§4), now shown to also block the "orthogonal source" path:
even a decorrelated model's errors can't be gated away by cheap per-proposal features.

Keep V17 `56103401` at public **0.39**. Evidence: `outputs/v54_gate/gate.json`,
`outputs/v54_gate/fit_features.npz`.

## Remaining levers (lower EV, for a future session)
1. **Train the quality gate end-to-end into V52** (FN-weighted BCE / focal) rather than
   post-hoc — change what the model is confident about, not how we score it. The post-hoc
   finding says the *information* for separation isn't in cheap geometry; a retrained
   model might put it in the prob map itself.
2. **Full-2048 V52** to sharpen thin structures (standalone recall is already 0.60+;
   the issue is FP precision, which higher resolution + higher clДice-weight attack).
3. **Richer per-proposal features that need the prob map** (prob-gradient along skeleton,
   boundary sharpness) PLUS fixing V52 inference determinism (seed/sorted CC, no TTA
   resize jitter) so a clean score-only A/B becomes possible. Higher cost.
