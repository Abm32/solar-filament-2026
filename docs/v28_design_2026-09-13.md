# V28 design — exact-serving tile-aware proposal utility scorer

Frozen **2026-09-13 before tune/audit evaluation**. This design follows the successful V28 physical-file-grouped OOF feasibility test. It does not authorize audit, test inference, CSV export, or submission.

## Result that authorizes this stage

The exact V26 `iou030` hybrid serving cohort completed over all 566 frozen training files:

- 14,127 independently refined proposals;
- 4,638 proposals positive for at least one annotator;
- exact shard coverage 142/142/141/141 files, with matching JSON/NPZ counts;
- four deterministic physical-filename folds, so no proposal is scored by a model trained on its physical file.

Against mandatory detector confidence, the predeclared candidate `confidence × predicted_utility` improved:

| metric | confidence | OOF product | delta | required |
| --- | ---: | ---: | ---: | ---: |
| TP-vs-FP AUC | 0.865035 | 0.877062 | +0.012028 | >+0.010 |
| utility Spearman | 0.618821 | 0.636480 | +0.017659 | >+0.010 |
| cross-fitted expected-PQ surrogate | 0.464647 | 0.472209 | +0.007562 | >+0.005 |

All gates passed. Every held-out fold independently selected product threshold **0.10** from the frozen threshold grid. Artifacts are preserved in `outputs/v28_utility_azure/`.

## Hypothesis

V26 established that native slicing exposes missed small filaments but detector confidence cannot separate useful tile proposals from false positives. V28 tests one narrow mechanism: a crop scorer trained on the exact serving population can preserve V26's added true positives while suppressing enough false positives to beat both V17 and V26's confidence-ranked hybrid.

This is not another detector, tile-geometry, threshold, or refiner search. It changes only proposal ordering and the final fixed score gate.

## Frozen model and target

Input crop is 64×64 with four uint8 channels:

1. raw grayscale image;
2. detector proposal mask;
3. independently refined binary mask;
4. native refiner probability.

Scalar inputs are detector confidence, log proposal area, refined/proposal area ratio, normalized crop width/height, and full/tile source indicators.

The network is the exact feasibility model: three convolution blocks (16/32/64 channels), global average pooling, a 64-unit head with dropout 0.15, and two sigmoid outputs. Targets are annotator-aware thresholded-IoU utility and annotator positive fraction. Loss is Smooth-L1 utility plus binary cross-entropy fraction.

Full training is fixed at:

- all 14,127 proposals;
- seed `20260912`;
- 6 epochs;
- batch 128;
- AdamW, learning rate `2e-4`, weight decay `1e-4`;
- no checkpoint or epoch selection.

## Frozen serving rule

The only V28 candidate score is:

`detector_confidence × predicted_utility`

The only score threshold is **0.10**, unanimously selected in all four OOF folds before tune was opened. Refined masks are ordered by this product score and passed through the same minimum-area/disjoint pixel-ownership semantics as V17/V26. Product scores do not modify mask probabilities or geometry.

Two regression baselines must reproduce exactly on tune before V28 is trusted:

- V17 control: `iou_sum=481.0093129235512`, 704 TP / 306 FP / 430 FN, PQ 0.44870271727943206;
- V26 hybrid confidence: `iou_sum=465.5503995207298`, 678 TP / 339 FP / 456 FN, PQ 0.43286880476125505.

## Tune gates

Audit opens once only if the fixed V28 candidate satisfies **all**:

1. tune PQ ≥ **0.45870271727943207** (V17 +0.010);
2. tune PQ ≥ exact V26 hybrid-confidence PQ + **0.010**;
3. tune TP ≥ V17 control TP (at least 704);
4. tune FP ≤ 120% of V17 control FP (at most 367).

These gates require both score improvement and conversion of V26's raw recall into final matched instances. They cannot be weakened after tune.

If any gate fails, close V28 without audit/test/export. Do not change epochs, product formula, threshold, crop channels, tile geometry, refiner threshold, ownership, or gates.

## Audit and export policy

If tune authorizes audit, evaluate exactly the frozen V28 candidate once on canonical 47 files / 67 annotator records / 459 GT. No audit grid or threshold selection is allowed. Export becomes eligible only if audit PQ ≥ **0.470763** (V17 audit bar).

Even if audit clears, this evaluator cannot access test images or produce a CSV. A separate frozen test exporter requires explicit implementation and validation. Kaggle upload remains a separate explicit decision after submission validation and allowance checks.
