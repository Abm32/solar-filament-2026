# V34 design — expert-spine bilateral width-profile representation

Frozen **2026-09-14 before implementation or any V34 oracle measurement**.

## Motivation and separation from closed tracks

V31 showed that expert spines carry unusually strong instance information, but its dense skeleton-aware distance target and watershed decoder failed the predeclared representation gate. V32/V33 showed that exact Omnipose fields reconstruct source masks but two dense image-to-field models could not pass a 16-record overfit gate. V34 is not a threshold, decoder, loss, or architecture rescue for either track.

V34 tests a different representation: each filament is an **ordered expert centerline with separate left and right widths along the local normal**. Reconstruction is a geometric ribbon/tube, not watershed, connected components over an energy field, Euler integration, object queries, boxes, or proposal refinement.

The representation is attractive for this dataset because all 8,199 annotations have expert polylines, median effective width is about 11 px, and exact same-record overlaps are rare. Its principal risk is that one ordered centerline with a local bilateral profile cannot represent branched, strongly non-normal, or irregular masks.

## Hypothesis

> Exact ordered expert spines plus source-measured bilateral normal widths reconstruct canonical fit+tune instances at combined strict PQ >=0.95 and recall >=0.99, with materially better fidelity than a symmetric-width tube.

This is only a representation-ceiling claim. Passing does not imply an image model can predict the representation or improve V17.

The oracle uses annotation geometry only and does not read image pixels.

## Frozen ordered-spine construction

For each source polygon mask independently:

1. Densify each consecutive expert-polyline segment at `ceil(max(|dx|,|dy|))` intervals, including the final endpoint.
2. Round each dense `(x,y)` sample to integer pixels.
3. Project each sample to the nearest source-foreground pixel within radius 3, using deterministic `(distance²,y,x)` tie order.
4. Remove only consecutive duplicate projected samples.
5. Reject the instance as invalid if fewer than two ordered samples remain.
6. Use the resulting ordered projected points directly; do not skeletonize, smooth, simplify, reconnect, or reorder them.

No parameter is chosen from oracle PQ.

## Frozen bilateral width measurement

At projected point `p_i`, estimate the tangent from `p_{min(n-1,i+3)} - p_{max(0,i-3)}`. If this vector is zero, expand symmetrically up to the first nonzero ordered pair; if none exists, mark the instance invalid. Normalize the perpendicular `(-dy,dx)` as the left normal; its negation is right.

For each side independently:

- sample from the projected center at distances `0.25, 0.50, ...` pixels;
- nearest-neighbor raster membership uses `round(y), round(x)`;
- stop at the first out-of-mask or out-of-image sample;
- width is the last in-mask distance, capped at 128 px;
- no interpolation, median filter, clipping by population statistics, or gap repair is permitted.

The cap is a safety bound, not a tuned morphology parameter. Report how many rays reach it.

## Frozen reconstructions

### Primary: bilateral ribbon

For each center sample, form left and right endpoints using its separately measured widths. For every consecutive sample pair, rasterize the quadrilateral `[left_i, left_{i+1}, right_{i+1}, right_i]` with OpenCV integer rounding and `LINE_8`. Also rasterize each cross-section line from left to right and fill the two endpoint cross-sections. The union is one predicted instance. Remove it only if area is below 20 px.

### Matched control: symmetric ribbon

Use the identical ordered points, tangents, rasterizer, and decoder, replacing both side widths at each point by `(left_width + right_width) / 2`. No other difference is allowed.

Predicted instances remain independent during oracle scoring; the five known complete-dataset same-record overlap cases are not forcibly assigned because the source targets themselves overlap. Report overlap records separately.

## G0 — integrity and implementation parity

Before full execution require:

- annotation SHA-256 `5da9e92b5a1a1947fd5d57adb6688269625c48ec1ef884daf2a01618c9ed54a1`;
- exact fit/tune populations above and no audit/test path in runtime;
- a horizontal synthetic asymmetric tube reconstructs exactly under bilateral widths;
- reversing centerline order produces an identical reconstructed mask;
- symmetric source widths make bilateral and symmetric reconstructions identical;
- deterministic repeated execution is byte-identical.

Failure closes V34.

## G1 — full fit+tune representation oracle

Run both reconstructions on every fit+tune annotator record and score strict `IoU > 0.5` with the project’s canonical global PQ arithmetic. The representation gate passes only if all hold:

- valid ordered spine instances / 7,740 >= **0.995**;
- bilateral combined global PQ >= **0.95**;
- bilateral fit global PQ >= **0.94**;
- bilateral tune global PQ >= **0.94**;
- bilateral combined recall >= **0.99**;
- bilateral zero-PQ records <= **1%**;
- bilateral median matched IoU >= **0.90**;
- bilateral PQ minus symmetric PQ >= **0.005**, or bilateral PQ >= **0.975** if the symmetric control is already too faithful to separate;
- capped rays <= **0.01%**;
- all outputs deterministic and finite.

The alternative `bilateral >=0.975` clause was frozen because a near-perfect symmetric tube would make asymmetry unnecessary while still validating the broader ordered-spine/width representation.

If any G1 gate fails, close V34. Do not change tangent radius, projection radius, ray step/cap, endpoint treatment, rasterization, area floor, or gates after observation.

## Conditional G2 — numerical predictability gate

G2 is not implemented or authorized until G1 passes. If authorized, freeze a new design before code that predicts rasterized spine occupancy and bilateral widths on the same 16 fit records used by prior overfit gates. It must use contamination-safe generic pretraining and reach decoded training PQ >=0.85 before full-population training can be considered.

No architecture, loss, sampling, threshold, GPU, tune, audit, test, export, or submission decision is part of G1.

## Stop rules

Do not rescue V34 with:

- morphology-derived or public spines;
- source-mask pixels supplied at image-model inference;
- width smoothing or percentile clipping;
- polygon contour residuals;
- multiple centerlines per source instance;
- tangent/normal/ray-step sweeps;
- audit inspection;
- V17 blending;
- test inference or submission without separately frozen downstream gates.

If V34 fails G1, the remaining serious clean architecture path is a separately costed generic-pretrained MaskDINO/RF-DETR-Seg study, not another dense field or tube variant.

## Final result — closed at G1

The corrected one-to-one full oracle completed over all 1,087 fit+tune annotator records / 7,740 GT instances:

- ordered-spine validity: **1.000000** (7,740/7,740);
- bilateral combined PQ: **0.945962846**;
- bilateral SQ: **0.946085079**;
- bilateral recall: **0.999870801**;
- bilateral TP / FP / FN: **7,739 / 1 / 1**;
- median matched IoU: **0.958979034**;
- fit PQ: **0.945582610**;
- tune PQ: **0.948177873**;
- zero-PQ records: **0/1,087**;
- capped-ray fraction: `4.330158e-06`;
- symmetric control PQ: **0.764011336**;
- bilateral delta: **+0.181951510**.

All frozen gates passed except combined PQ >=0.95; the miss is **-0.004037154**. Therefore `g1_passed=false` and `gpu_authorized=false`. V34 is closed without G2 design, image-model work, audit/test access, CSV, export, or submission. The strong bilateral-control delta establishes that ordered asymmetry is real and useful, but it does not permit weakening an observed gate.

The first full run exposed a legacy strict-PQ accounting shortcut that can overcount TP when rare overlapping masks create multiple IoU>0.5 edges. Geometry was unchanged; scoring was corrected to deterministic one-to-one maximum-weight assignment, pinned by a synthetic overlap test, and the complete oracle was rerun. The corrected result above is final.
