# V16 design — detector retrain, `mask_ratio=1` vs `mask_ratio=2`

Written **before** the run, 8 September 2026, after V15's clean negative closed
the refiner-capacity axis. Directly executes `ceiling_analysis_2026-09-07.md` §8
item 4, the last unranked item on that list.

## Why this run exists

Three separate attempts to improve the crop-refiner head (V11 ResNet18, V14
ResNet34-broken, V15 ResNet34-fixed) have not beaten V13's mean matched IoU of
0.6855. V15 in particular measured a *correctly initialised* ResNet34 losing to
V11's ResNet18 (0.6777 vs 0.6855) under identical selection — the refiner-capacity
lever is closed on solid evidence, not a broken run.

`ceiling_analysis_2026-09-07.md` §4 established the actual structural cap: no raw
YOLO proposal, across all 1,134 GT instances, exceeds IoU 0.8734. Mean raw IoU is
0.5842. The refiner cannot exceed what the proposal gives it — measured directly
(`refined_constrained` ≈ `refined_free`, i.e. the refiner is not even trying to
leave the proposal envelope; the cap is the proposal, not the clamp).

The identified mechanism: YOLO segmentation emits masks from a prototype layer at
1/4 of `imgsz` (256×256 protos at `imgsz=1024`), upsampled 8x to 2048x2048.
`mask_ratio=2` (current config, `configs/yolo_seg.yaml` and every detector run to
date: V6, V12/E022, this project's `solar_base.py`) **further halves** the mask
resolution used for training targets, per Ultralytics's own documentation of the
parameter. `mask_ratio=1` removes that halving.

E022 (V12) already tested detector-training resolution (1024 vs 1536) and found
raising `imgsz` alone does not pay for itself in PQ — but E022 fixed `mask_ratio=2`
throughout and varied only `imgsz`. **`mask_ratio` was never varied by any prior
experiment.** This run isolates it, following V12's exact harness and discipline.

## Design: adapt V12's harness, replace the varying axis

V12 varied `imgsz` (1024 vs 1536) with `mask_ratio=2` fixed. V16 mirrors that
structure exactly, but varies `mask_ratio` (1 vs 2) with `imgsz=1024` fixed in
both arms and at inference. This isolates the one untested variable.

```
V12 (E022, done)  = imgsz {1024, 1536} x mask_ratio=2 (fixed)      -> gate FAILED
V16 (this run)    = imgsz=1024 (fixed) x mask_ratio {1, 2}          -> untested
```

| | training imgsz | mask_ratio | inference imgsz |
| --- | --- | --- | --- |
| control | 1024 (frozen V6) | 2 (as shipped) | 1024 |
| arm_r2  | 1024 | 2 | 1024 |
| arm_r1  | 1024 | 1 | 1024 |

`arm_r2` is a same-budget retrain with the *shipped* mask_ratio, included as an
internal check: if `arm_r2` does not approximately reproduce the control's
detector-level quality under a fresh 20-epoch continuation, the harness itself
(not `mask_ratio`) is suspect and `arm_r1`'s result cannot be trusted in isolation.

Only `mask_ratio` differs between `arm_r1` and `arm_r2` — enforced at runtime by
`verify_matched_budget`, copied from V12 with the excluded key changed from
`imgsz` to `mask_ratio`.

Everything else is V12's audited, already-verified recipe unchanged: warm-started
from the pinned V6 checkpoint (`0abf568f...a38b8`), 20 epochs, `resume=False`,
AdamW lr0=1e-4 lrf=0.1, warmup 1 epoch, nbs=64, seed 42 deterministic, single_cls,
`overlap_mask=False`, global batch 4 (fallback 2 if OOM, applied to both arms),
V6's exact augmentation. Dataset: the same 566/141 grouped split, 937/6,606
train entries/instances, reconstructed and asserted identically to V12.

Refiner, grouping (`flip_consensus`), thresholds, confidence gate (0.40), min
area (20), and pixel ownership all stay frozen at V12/V13's settings — this run
isolates the detector's mask target resolution, nothing downstream.

## Predeclared bars, fixed before any V16 number is observed

- **Harness sanity check:** `arm_r2` (same mask_ratio as the control, fresh
  20-epoch continuation) must score within a reasonable band of the control on
  tune PQ. This is not a promotion gate — it is a check that the retrain-and-
  evaluate pipeline itself is not the source of any observed `arm_r1` difference.
  No fixed numeric bar; report the delta and reason about it explicitly rather
  than gating on an arbitrary threshold.
- **SUBMIT_BAR** (authorises exporting a CSV): tune PQ ≥ **0.441777** (V13, best
  measured) **and** audit ≥ **0.450130** (E015 floor).
- **PROMOTION_GATE** (authorises calling it a real gain and considering a
  submission): tune ≥ V13 + **0.010** with audit ≥ V13's audit (0.464644). Per
  E024, do not spend a submission below this margin — it will not be visible at
  two public decimals.
- **Frozen control first.** Must reproduce E015's exact tune/audit counts
  (`[426.5473399071962, 626, 211, 508]` / `[182.75261599994462, 265, 88, 194]`)
  and its exported CSV must hash to
  `bf11690e9bcce73b0c627096cc1198d9fb0916650f7fa4b3f08f1167bb76bde9`. Abort
  otherwise, exactly as V12/V13/V15 did.
- Selection is **tune-PQ only** across the declared candidates; audit never
  selects, per every prior run's discipline.

## What "mean raw proposal IoU improves" would mean, and what would not

This run changes the detector's *training target resolution*, not the refiner.
A positive result would show up as **higher mean raw proposal IoU** before any
refinement — a new, harder ceiling than 0.8734/0.5842. If raw proposal quality
does not move, `mask_ratio` is not the lever either, and the honest conclusion is
that YOLO's coarse-instance-segmentation architecture itself (not a tunable
parameter within it) is the ceiling — at which point 0.55 is not reachable by
incremental tuning of this pipeline at all, and that should be reported plainly
rather than searched for further.

## Cost estimate

Two 20-epoch YOLO11s-seg training runs at `imgsz=1024`, global batch 4 — the same
class of cost as E022/V12 (that run's log shows ~1,946,568 bytes over roughly
comparable wall-clock; V12's own audit estimated the pair at a few thousand GPU-s).
Budget ~4,000-5,000 GPU-s including evaluation. Quota checked 2026-09-08: **64,305
s remaining** of 108,000, refresh 2026-09-12. Comfortable headroom for this run
plus a smoke test first.

## Honest expectation

If `mask_ratio=1` meaningfully raises the raw-proposal IoU ceiling, the realistic
next step is re-measuring the full pipeline (refiner + selection) on top of the
new detector — a V17-scale follow-up, not free. This run only tests whether the
lever exists, following `ceiling_analysis`'s own ranking: item 4, cheap, untested,
last on the list. If it is negative, the ceiling analysis's warning stands: the
credible reachable band for this pipeline is **0.40–0.44 public**, not 0.55, and
that should be stated to the user rather than continuing to search for a lever
that does not exist in this architecture.
